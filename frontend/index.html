🎓 2nd Year Mid-Semester Viva & Project Defense Guide

💡 1-Sentence Project Summary (Slide 2)

"An intelligent full-loop web application that calculates personal greenhouse gas emissions across 7 categories, applies AI/ML to analyze behavioral patterns, predicts future emissions, and generates a Unified Green Score to motivate sustainable lifestyle changes."

⚙️ Full Loop Architecture (Slide 4 & 7)

Unlike existing static calculators that stop at a single number, our project implements the complete closed loop:

User Activity Input → CO₂e Calculation (IPCC Factors) → Storage (MySQL) → AI Behavior Analysis → Recommendation Engine → Scikit-learn Future Prediction → Unified Green Score → Gamified Motivation

📊 Scientific Calculation Formula (Slide 10)

Emission (kg CO₂e) = Activity Amount × Verified Emission Factor • Transportation: 20 km × 0.12 kg CO₂e/km = 2.4 kg CO₂e • Electricity: 5 kWh × 0.70 kg CO₂e/kWh = 3.5 kg CO₂e • Sourced from DEFRA (UK GHG Factors) & Central Electricity Authority (India)

🧠 Machine Learning & Architecture

  • Emission Predictor: Fits an Ordinary Least Squares (OLS) Linear Regression model (y = mx + c) dynamically using Scikit-learn's LinearRegression directly on the user's own logged historical daily totals (no pre-trained model or static weights). If the backend is unreachable, the browser's local engine performs the identical regression calculation.
  • Data Persistence: SQLite relational database (ecotrack.db) stores activities with timestamp, category, amount, and server-calculated CO2e using strictly parameterized queries.
  • Offline Fallback & Sync: If the Flask server is stopped or opened via file://, the frontend operates completely offline, queues logs with a pending sync tag in localStorage, and automatically syncs them to SQLite without duplicates once the server reconnects.
  • Emission Factor Sources: Only Petrol Car (DEFRA), Diesel Car (DEFRA), and Grid Electricity (CEA / IPCC) carry scientific citations (verified: true). All other factors are domain project estimates (verified: false).

🔌 REST API Endpoints

The frontend communicates with the Python Flask server via standard JSON endpoints with strict input validation:

GET /api/health -> Server heartbeat & status GET /api/factors -> Verified & estimated emission factors GET /api/config -> Benchmarks, weights, and limits POST /api/activities -> Saves activity to SQLite (computes CO2e) GET /api/activities -> Queries user activities (newest first) DELETE /api/activities/<id> -> Deletes activity from SQLite GET /api/summary?days=N -> Continuous daily category totals POST /api/predict -> Scikit-learn LinearRegression forecast POST /api/recommendations -> Targeted reduction recommendations

❓ Top 3 Examiner Viva Questions & Answers

Q1: Why do we need ML if emissions use standard factors?
Ans: Activity factors compute static historical footprints (Amount × Factor), but Scikit-learn Linear Regression dynamically models the user's emission velocity and rate of change, projecting a 7-day trajectory and simulating the exact quantitative impact of lifestyle habit modifications.

Q2: What is the Unified Green Score?
Ans: It normalizes emissions onto an intuitive 0-100 scale benchmarked against the Paris Agreement 1.5°C climate target (4.1 kg/day) and national averages (9.8 kg/day).

Q3: How is the ML model trained?
Ans: There is no pre-trained static dataset. The Scikit-learn LinearRegression model is fit on-the-fly per user directly over their own chronological daily emission log totals from SQLite (or browser fallback), guaranteeing predictions reflect personal habits.
